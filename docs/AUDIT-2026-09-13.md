## Limits and follow-up verification

- Native window click-through, real clipboard behavior, OS dialog focus, installer upgrade, and long-running soak behavior have not been exercised. Component tests do not substitute for those checks.
- The launch resolver supports the standard npm Pi installation (current and former package names), as used on this machine. Alternate custom shims and other operating systems need separate validation.
- Normal stop/restart/app-exit process cleanup is implemented; Windows descendant cleanup after an unexpected parent crash is not proved by the suite.
- Companion content revisions detect external edits but do not constitute a cross-process filesystem lock. Two independent writers can still race between revision check and replacement. Existing Pi reload/restart semantics remain authoritative for applying file-backed changes.
- Native async RPC dispatch is compiled and reviewed; the exact Tauri IPC + extension-dialog round trip still needs a desktop smoke test.
- Sidebar history is refreshed on settled runs/navigation, not by an external filesystem watcher. Changes made by another application may require refresh/navigation.
- Session headers and message extraction, markdown sanitization, sidebar grouping/filtering, capabilities, entrypoints, and build configuration were inspected or exercised by their existing tests. This was not a dependency-CVE audit, provider/model benchmark, or pixel-level design review.
- No live companion installation, app installation, deployment, or push is part of this change. The updated companion source must be installed explicitly through Leftleg before its new write behavior is used with a live Pi process.
