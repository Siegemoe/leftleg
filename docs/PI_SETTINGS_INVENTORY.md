## Verified integration constraints

1. Standard RPC exposes model/thinking/queue changes and auto-compaction/retry switches, but **no general `get_settings`, `set_settings`, package-management, trust-management, or extension-settings RPC**. See `PI_ROOT/docs/rpc.md` and `dist/modes/rpc/rpc-mode.js`.
2. Built-in `/settings`, `/login`, `/hotkeys`, etc. are TUI handlers, not ordinary RPC commands. `get_commands` explicitly excludes built-in TUI commands. Sending arbitrary TUI commands through `prompt` is not a configuration API.
3. Extension `ctx.hasUI` is true in RPC, but `ctx.ui.custom()` returns undefined; custom terminal panels cannot be embedded by merely invoking their commands. Simple select/confirm/input/editor dialogs and notify/status/widget events are supported. Some extension checks only use `hasUI`, so command presence does not prove GUI compatibility.
4. RPC `set_model` and `set_thinking_level` call the session methods without `persist`; they change current-session choices, not saved startup defaults. `set_steering_mode`, `set_follow_up_mode`, auto-compaction and auto-retry setters do persist through SettingsManager. A current-session control must not be mislabeled as a project-only saved setting. Read actual setter semantics per operation.
5. `get_available_models` returns the current model-runtime snapshot; it does not itself refresh `models.json`. Extension `ctx.modelRegistry.refresh()` is public and async. Verify refresh behavior before claiming a new provider/model is available.
6. Project trust gates project-local settings/resources. With no saved decision, RPC uses global `defaultProjectTrust`; its default `ask` ignores project resources without prompting. Extensions or launch flags can alter the decision. The absent trust file alone does not prove a particular live process is untrusted; query effective trust.
7. `defaultTools` controls built-ins only. Extension/custom tools remain enabled. `--tools` is a strict all-tool allowlist; `--exclude-tools` filters all tools; `--no-tools` and `--no-builtin-tools` differ. Pi 0.85.1 has native `powershell` as well as `bash`.
8. Pi's public extension API exposes `getAllTools`, `getActiveTools`, `setActiveTools`, effective system-prompt inspection, trust inspection, and command-context `reload()`. SettingsManager, ModelRuntime, and resource/package managers are exported, but not every object is directly available on ExtensionContext. Check exports/signatures rather than using private session fields or obsolete AuthStorage examples.
9. Leftleg launches one Pi process per project. Global edits affect shared on-disk configuration; already-running processes may have different loaded snapshots. Never label all processes updated just because one save succeeded.

## Core coverage checklist and sources

Use **all** fields from `PI_ROOT/dist/core/settings-manager.d.ts` plus `docs/settings.md`; the following grouping is a coverage aid, not a replacement schema:

- Models/thinking: `defaultProvider`, `defaultModel`, `defaultThinkingLevel`, `modelThinkingLevels`, `enabledModels`, `thinkingBudgets.{minimal,low,medium,high}`. Runtime levels must come from Pi; source includes off/minimal/low/medium/high/xhigh/max.
- Context/reliability: `compaction.{enabled,reserveTokens,keepRecentTokens}`, `branchSummary.{reserveTokens,skipPrompt}`, `retry.{enabled,maxRetries,baseDelayMs,provider.{timeoutMs,maxRetries,maxRetryDelayMs}}`, `steeringMode`, `followUpMode`, `images.{autoResize,blockImages}`.
- Network/process: `transport`, `httpIdleTimeoutMs`, `websocketConnectTimeoutMs`, `httpProxy` (global only), `shellPath`, `shellCommandPrefix`, `npmCommand`, `sessionDir`, `defaultTools`.
- Resources: `packages` string/object forms, `autoload`, per-package extensions/skills/prompts/themes filters; top-level resource arrays, glob/force include/exclude semantics, `enableSkillCommands`. Resolve package/global/project/CLI discovery, collisions and trust.
- Trust/privacy: `defaultProjectTrust` (global only), Pi-owned trust decisions, `enableInstallTelemetry`, `enableAnalytics`, `warnings.anthropicExtraUsage`. `trackingId` and `lastChangelogVersion` are internal metadata, not ordinary editable preferences. Update checks and install telemetry are independent.
- TUI/display: `theme`, `externalEditor`, `hideThinkingBlock`, `showCacheMissNotices`, `quietStartup`, `collapseChangelog`, `doubleEscapeAction`, `treeFilterMode`, `editorPaddingX`, `outputPad`, `autocompleteMaxVisible`, `showHardwareCursor`, `tuiMode`, `fullscreenExitOutput`, `fullscreenScrollbar`, `fullscreenCopyOnSelect`, `terminal.*`, `markdown.{codeBlockIndent,mermaid}`. `terminal.showTerminalProgress` appears in the type declaration; trace source/defaults rather than silently omitting source-only fields. These Pi presentation choices must be labeled separately from Leftleg appearance.
- Models/auth: `docs/models.md`, `docs/providers.md`, `dist/core/model-runtime.d.ts`, `dist/core/model-registry.d.ts`; custom provider/model fields, overrides, API compatibility, credential source/status/login/logout. `ModelRuntime` supplies public login/logout/refresh APIs; do not assume old AuthStorage imports are still present.
- Prompts/resources: `README.md` Context Files/System Prompt sections, `docs/skills.md`, `docs/prompt-templates.md`, `docs/packages.md`, resource-loader source. AGENTS/CLAUDE/AGENTS.override ancestry, global/project SYSTEM.md and APPEND_SYSTEM.md, skills/templates/themes and explicit launch overrides. `USER.md` is not a built-in automatically discovered Pi file in these sources.
- Launch/environment: `docs/environment-variables.md`, README CLI tables and parser source: agent directory, session root, offline/version checks/telemetry, transport/cache/proxy variables, resource flags, tool flags, context/system-prompt flags, extension-registered flags. Inspect only relevant variables and redact sensitive values. Source configuration should be distinguished from runtime markers such as `PI_SESSION_ID`.
- Keyboard: `docs/keybindings.md` and theme docs. Pi TUI shortcuts/themes are editable configuration, but do not apply automatically to the webview.

Nested settings objects merge according to Pi; arrays may replace or have resource-specific merging behavior. Extension resolvers differ. A GUI cannot truthfully display a universal precedence chain for every extension without consulting its resolver.
